# Lumber editor implementation plan

> Execution: inline using executing-plans. User explicitly requested implementation without further approval gates.

Goal: deliver the usable blueprint building editor described in ../specs/2026-10-03-lumber-building-simulator-design.md.
Architecture: catalog/geometry, world/history/spatial index, batched rendering, interaction, and local persistence remain separate modules.
Stack: TypeScript, Three.js, Vite, Vitest, Playwright.

## Global constraints
- Preserve every placed item; no artificial piece cap.
- Exact LT2 fidelity requires evidence; reconstructed details are labeled.
- No physics or per-item frame callback for static construction.
- Desktop keyboard/mouse first; no deployment or external account changes.

## Review focus
- Instance-slot compaction must not change selected IDs.
- Thin/rotated pieces must sit flush on support surfaces.
- Malformed imports must not replace the current project.
- Undo following move/delete and reload must preserve transforms.
- Camera focus loss must release movement keys.

## Tasks
- [x] 1. Catalog and world: 69 unique entries, precise thin dimensions, rotation-aware support offsets, stable ID deletion, history, import validation. Implemented src/catalog.ts, geometry.ts, world.ts, placement.ts, project.ts. Core tests pass.
- [x] 2. Renderer: chunk-owned instancing, ID mappings, affected-chunk rebuilds, culling, material caches, camera, ghost and outline. Geometry bounds, deletion, ray traversal, camera controls and rendering checked.
- [x] 3. Editor: app shell, categorized thumbnail catalog, finishes, selection and transform controls, placement, keyboard, example, settings. Browser flows pass.
- [x] 4. Persistence: atomic IndexedDB project saves, validation, previous-snapshot recovery, import/export and error states. Real browser tests pass.
- [x] 5. Delivery: portable ZIP and production-site check complete. Browser suite, screenshots, 1k/10k/100k stress measurements and review fixes recorded. Packaged site starts without a build, has no development API, and passes placement, save/reload and compact-width checks.

## Interfaces
CatalogItem {id,name,category,size,shape}; Piece {id,item,wood,position,rotation}; Project {version,name,pieces}; World manages Piece records and dirty chunk keys. Renderer consumes World and exposes picking by stable ID. Editor owns commands; storage consumes validated Project records.

## Execution ledger
- Scope approval: user said "yes just make the thing"; proceed directly.
- Repository is newly created and isolated from other projects; implementation uses build/editor branch.
- Fidelity: indexed community table has 69 entries (3 doors, 22 wedges/stairs, 24 walls/fences, 8 floors/tiles, 10 furniture, 2 other). Seven furniture blueprints belong to Fancy Furnishings; the chair and two tables account for the other three. Catalog follows the explicit table.
- Ruling: start with WebGL2 renderer for a small, stable desktop delivery and validate batching there; WebGPU is a future backend optimization, not a prerequisite for instancing. Report this deviation.
- Ruling: local world records stay resident for instant editing; GPU chunks stream by distance. True disk-paged world records remain an explicit scale limitation until measured demand justifies additional complexity.
- Verification: 18 core tests and 7 browser scenarios passed, followed by a successful production build on 2026-10-03. Three.js triggers Vite's advisory about a bundle over 500 kB; compressed application JS is approximately 166 kB.
- Review fixes: history event ordering, original finish mutation during duplicate preview, upward free-camera clamp, stale inspector state, catalog row sizing, oblique-plane support. Each behavioral fix has regression evidence.
- Performance refinement: ray traversal plus cached bounds reduced dense 100k pointer picking from 119.6 ms to 13.9 ms. Dense scene median frame time remained 16.7 ms. See docs/VALIDATION.md for hardware and limits.
- Deferred spec items are explicit in docs/VALIDATION.md: exact live LT2 acceptance, disk paging, incremental chunk saves, worker import/export, overview proxies, WebGPU backend, adaptive quality recovery. Deliverable is a usable first version, not certified full parity.
